## 2026-10-03 · 012 · M2 操作票据、兼容门禁与断线队列

- **目标：** 将 Hub 授权结果绑定到 Agent 的单次请求，拒绝无票据、过期、替换参数和重放，并阻止旧 Agent 接收运维操作。
- **改动：** Hub/Agent 增加一致的签名票据协议；用节点现有 token 作为 HMAC 密钥，绑定用户、节点、动作、请求和参数摘要。Agent 统一接收入口在启动操作前消费票据。Hub 按认证报告的 M2 能力派发，终端、命令和文件全部进入签发路径；批量命令签发全部成功后才创建任务。WS 重连清除旧声明，队列重新检查身份、当前签名、节点能力，文件超时/取消清理尚未发送的操作。禁止上游自动更新及远程版本替换。
- **关键决定：** 有效期 90 秒；重放记录不淘汰未过期条目，满容量拒绝；进程重启拒绝启动前签发票据，不自动重跑。后台上传取消使用显式内部身份，外部缺失身份不会自动升级为内部调用。token 轮换及撤权使待发队列项失效。
- **验证：** Hub/Agent 编译通过；双端协议检查覆盖参数替换、错节点/错密钥、过期、未来时间、重启边界与并发重放。Agent 实际接收器配合临时目录/本机回传服务验证有效创建、重复不执行、无票据拒绝、签名有效但路径越界拒绝、能力关闭拒绝。Hub 队列检查覆盖旧节点、能力错配、撤权后重新授权不复活旧队列、取消和 token 轮换；M1 路由及文件回归通过。
- **失败与处理：** 首次 Hub 构建发现 `web/agent` 引用客户端业务包造成上游 utils 导入环，改为授权层与最小数据库模型读取；Agent 的报告原为 JSON 字节与匿名运维参数，增加一致参数类型并在现有报告中附加策略声明。重连后的排队消息改为等待新报告后发送。
- **边界：** HMAC 依赖节点 token 保密，不能抵御已控制 Hub/节点的攻击者；本机目录及能力仍独立检查。票据过期不取消已开始的操作；结果丢失需检查目标状态，不代表未执行。真实 Linux 用户切换、PTY 与 VPS 运行仍未验收，本轮未重建 Docker 镜像。
- **对应提交：** 本次提交；M2 本地策略前序提交 `23a7039`。
